# 数据库设计

> 数据库：MySQL 8，库名 `tour_planner`，字符集 utf8mb4
> 通用约定：
> - 主键 `id` 为自增 BIGINT；每张表都有 `created_at`、`updated_at`（DATETIME）
> - 金额用 DECIMAL(10,2)，单位元；坐标用高德坐标系（GCJ-02），DECIMAL(10,6)
> - 状态、类型等枚举值用 VARCHAR 存英文代码
> - 景点用“下线”代替删除，其余数据直接删除

## 表清单（第一版）

| 表 | 说明 |
|---|---|
| `sys_user` | 游客账号 |
| `district` | 旅游片区 |
| `poi` | 景点和餐厅 |
| `poi_open_rule` | 开放时间 |
| `poi_closed_date` | 闭馆日 |
| `trip` | 行程 |
| `trip_item` | 行程里的每一站 |

表关系：
- 一个片区有多个景点；
- 一个景点有多条开放时间和多个闭馆日；
- 一个用户有多个行程，一个行程有多站，每站对应一个景点。

## sys_user 游客账号

管理员不存数据库：只有一个固定账号，写在后端配置文件里（见接口文档第 7 节）。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| username | VARCHAR(32) | 用户名，唯一 |
| password | VARCHAR(100) | BCrypt 加密后的密码 |
| nickname | VARCHAR(32) | 昵称 |

## district 旅游片区

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| name | VARCHAR(50) | 片区名，比如“老城区（越秀、荔湾）” |
| sort | INT | 排序，数字小的在前 |

## poi 景点和餐厅

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| type | VARCHAR(16) | `SCENIC` 景点 / `RESTAURANT` 餐厅 |
| name | VARCHAR(50) | 名称 |
| district_id | BIGINT | 所属片区 |
| admin_area | VARCHAR(20) | 行政区，比如“荔湾区”，只用于展示 |
| address | VARCHAR(200) | 地址 |
| lng | DECIMAL(10,6) | 经度 |
| lat | DECIMAL(10,6) | 纬度 |
| intro | TEXT | 简介 |
| illustration | VARCHAR(32) | 插画名，对应前端插画库里的一幅 |
| official_url | VARCHAR(255) | 官网地址，可为空 |
| stay_minutes | INT | 建议游玩时长；餐厅填用餐时长 |
| full_day | TINYINT | 是否全天型景点，1 是 0 否 |
| ticket_price | DECIMAL(10,2) | 门票参考价，0 表示免费；餐厅为空 |
| avg_cost | DECIMAL(10,2) | 人均消费，只有餐厅填 |
| rating | DECIMAL(2,1) | 评分，比如 4.7 |
| tags | VARCHAR(200) | 标签，英文逗号分隔，比如“历史人文,适合长辈,室内” |
| status | VARCHAR(16) | `ONLINE` 上线 / `OFFLINE` 下线 |

## poi_open_rule 开放时间

一个景点可以有多条规则，比如周二到周日一条、周一不开放就不写。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| poi_id | BIGINT | 景点 |
| weekdays | VARCHAR(20) | 适用的星期，英文逗号分隔，1 表示周一、7 表示周日，比如“2,3,4,5,6,7” |
| open_time | TIME | 开门时间 |
| close_time | TIME | 关门时间 |
| last_entry_time | TIME | 停止入场时间，可为空（为空按关门时间算） |

## poi_closed_date 闭馆日

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| poi_id | BIGINT | 景点 |
| closed_date | DATE | 闭馆日期 |
| reason | VARCHAR(100) | 原因，比如“设备检修” |

同一个景点的同一天只能设一次闭馆日（`poi_id` + `closed_date` 唯一）。

## trip 行程

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| user_id | BIGINT | 所属用户 |
| title | VARCHAR(50) | 标题，比如“周六，带爸妈逛老城区” |
| trip_date | DATE | 出行日期 |
| prompt | VARCHAR(500) | 需求原话：对话里被识别为规划的消息，用“；”连接 |
| start_time | TIME | 出发时间 |
| adults | TINYINT | 成人数 |
| seniors | TINYINT | 老人数 |
| children | TINYINT | 儿童数 |
| budget | DECIMAL(10,2) | 预算 |
| pace | VARCHAR(16) | `RELAXED` 轻松 / `NORMAL` 适中 / `TIGHT` 紧凑 |
| district_ids | VARCHAR(100) | 想去的片区 id，英文逗号分隔，可为空 |
| must_poi_ids | VARCHAR(200) | 必去景点 id，英文逗号分隔，可为空 |
| avoid_poi_ids | VARCHAR(200) | 不去景点 id，英文逗号分隔，可为空 |
| interests | VARCHAR(100) | 兴趣标签，英文逗号分隔，可为空 |
| total_cost | DECIMAL(10,2) | 预计总花费 |

## trip_item 行程里的每一站

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| trip_id | BIGINT | 所属行程 |
| seq | INT | 第几站，从 1 开始 |
| poi_id | BIGINT | 景点或餐厅 |
| start_time | TIME | 到达并开始游玩的时间 |
| end_time | TIME | 离开时间 |
| cost | DECIMAL(10,2) | 这一站的花费（门票或餐费 × 人数） |
| next_mode | VARCHAR(16) | 去下一站的方式：`WALK` 步行 / `METRO` 地铁 / `TAXI` 打车；最后一站为空 |
| next_minutes | INT | 去下一站的耗时（分钟），估算值 |
| next_meters | INT | 去下一站的距离（米），估算值 |
| next_cost | DECIMAL(10,2) | 去下一站的交通费，估算值 |

## 后续批次再加的表

- **第二批**：`ticket_type` 票种、`ticket_slot` 分时段库存、`booking_order` 订单、`booking_order_item` 订单明细、`visitor` 出行人。
- 和小萧的对话记录第一版只保存在页面里，不建表；以后需要保存时再加会话表。
- **最后一批**：`travel_note` 游记、`note_comment` 评论、`note_like` 点赞。

建表脚本和示例数据在 `tour-server/src/main/resources/db/` 下：
- `schema.sql`：后端每次启动时执行，表已存在就跳过；
- `seed.sql`：第一次启动、片区表为空时导入一次，之后不再导入，免得覆盖后台改过的数据。
