# 需求分析

> 项目：城市文旅行程规划平台（毕业设计）
> 城市：广州
> 技术栈：Spring Boot + MyBatis（后端）、React（前端）、Python + LangChain + LangGraph + DeepSeek（AI 模块）

## 1. 系统定位

面向自由行游客的行程规划网站。游客打开“小萧”页面后，AI 助手小萧会先主动打招呼。游客像聊天一样说出出行想法，比如“周六带爸妈逛老城区，想轻松点，预算 500”。小萧会：
1. 判断用户是在闲聊，还是想规划行程；
2. 如果是闲聊，简单回应，再把话题引回出行；
3. 如果是规划，把需求整理成可修改的条件，结合景点的开放时间、路程和预算，排出一份当天走得通的行程；
4. 用时间线和地图展示结果。用户接着说“带上爸妈”“预算改成 300”，小萧就在原来的条件上修改后重排，用户满意就可以保存。

## 2. 用户角色

| 角色 | 说明 |
|---|---|
| 游客 | 注册登录、浏览景点、和小萧对话规划行程、管理自己的行程 |
| 管理员 | 只有一个固定账号；维护片区、景点、开放时间和闭馆日 |

## 3. 功能需求

### 3.2 小萧处理一条消息的过程

1. **敏感内容检查**：交给大模型之前，先按固定的词表检查这条消息，规则见 4.7。命中就不调用大模型，小萧用写好的话回复，不生成行程。
2. **识别意图**：判断这条消息是“闲聊”还是“规划”，判断方法见 4.3。闲聊只回复，不生成行程，页面上已有的行程保持不变。
3. **理解需求**：从消息里识别以下条件：
   - 日期（今天、明天、周六等）；
   - 出发时间；
   - 人数：成人、老人、儿童，比如“爸妈”算 2 位老人；
   - 预算、节奏（轻松 / 适中 / 紧凑）；
   - 必去和不去的景点、兴趣（历史人文、自然风光等）、想去的片区。

   第一次规划时，没说的条件用默认值：日期默认明天，出发时间 9:00，预算不限，节奏适中，1 位成人。

   已经有行程时，只修改这句话提到的条件，没提到的保留。比如先说“周六去老城区”，再说“带上爸妈”，日期仍是周六，只是加了 2 位老人。

   由大模型（DeepSeek）理解，会参考最近几条对话。大模型只负责理解和说话，排行程、校验由算法完成。
4. **排行程**：用贪心算法一站一站往后排，保证：
   - 到达时景点已开门、还没停止入场，离开时不晚于关门；
   - 当天不是闭馆日；
   - 累计花费不超过预算；
   - 结束时间不超过当天结束时间（按节奏定）。
5. **自动午餐**：11:30 到 13:30 之间，在上一站 6 公里内挑一家营业中的餐厅，用餐 60 分钟。附近没有收录的餐厅时提醒自行安排；出发时间已经过了 13:30 的不安排午餐。
6. **校验与提醒**：排完后逐站复核。排不进去的必去景点要给出原因，比如“周一闭馆”“超出预算”。
7. **结果内容**：
   - 意图、小萧的表情和回复；
   - 规划时还包括：条件标签，每一站的时间、地点、费用和到下一站的交通，总花费，执行步骤，提醒。

改条件标签或删站后直接重排，没有新消息，不再做敏感内容检查和识别意图。删掉的站自动加入“不去”条件，重排时不再选它。

对话记录只保存在当前页面，不存数据库。每次发消息带上最近 10 条，方便小萧理解上下文。刷新页面或点“新行程”后清空。

### 3.3 第二批

- 门票预约：分时段余票、下单、模拟支付、超时自动取消，保证并发下不超卖；管理员维护票种和库存
- 多日行程（2 到 3 天）
- 更聪明的对话修改：保留没改动的站，并说明前后变化（比如“下午换成室内的”）；拖拽调整顺序
- 天气提醒、用户管理、AI 调用记录

### 3.4 最后一批（可选）

- 游记社区：发布、点赞、评论，管理员审核
- 数据看板

## 4. AI 助手小萧

### 4.1 身份与性格

- 名字：小萧，平台的 AI 行程规划助手。
- 性格：傲娇的小男生，嘴上不太客气，其实很上心。
- 出现位置：
  - 首页输入框旁边，提示语是“跟小萧说说你的出行想法”；
  - 小萧页面，以对话的形式出现。

**人设规矩**
- 傲娇只放在回复的开头或结尾，一两句就够。行程安排和提醒必须清楚直接，不能因为人设变得含糊。
- 不嘲讽、不贬低用户，不说脏话，不涉及恋爱或调情，任何年龄的人看都合适。
- 闭馆、超预算、“开放时间和票价以官网为准”这类提醒必须明明白白说出来。
- 只说中文，回复简短。

### 4.2 能做什么（第一版）

- 打开页面时主动问候
- 分辨用户是在闲聊，还是想规划行程
- 听懂出行需求，整理成可修改的条件；用户接着说的话，在原条件上修改
- 在已收录的广州景点和餐厅里，排出一日行程
- 解释为什么这样排，提醒闭馆、超预算等问题

### 4.3 主动问候与意图识别

**主动问候**

打开小萧页面时，小萧先开口：从预置模板里随机挑一句，带上用户昵称。问候不调用大模型，打开页面马上就能看到。例如：
- “哼，小林，又来找我了？说吧，这次想去广州哪儿玩？”
- “来得正好，我刚好有空。哪天出门、几个人、预算多少，一次说清楚。”
- “又是你啊……先说好，太离谱的行程我可不排。想去哪？”

**意图**

| 意图 | 代码 | 哪些消息算 | 小萧的做法 |
|---|---|---|---|
| 规划 | `PLAN` | 说了出行想法（去哪、哪天、几个人、预算、节奏、想看什么）；或者已有行程时要改条件，比如“带上爸妈”“预算改成 300”“不去沙面了” | 理解需求并排行程，页面显示行程，回复里介绍安排 |
| 闲聊 | `CHAT` | 其余所有消息：打招呼、问小萧是谁、夸他或吐槽他、和出行无关的请求、问其他城市、问天气等 | 傲娇地回一两句，再把话题引回出行，不生成行程 |

**怎么判断**

- 把消息和最近几条对话交给大模型，按固定格式返回意图和小萧的表情。
- 判断错了也有补救：闲聊的回复会引导用户说出“哪天、去哪、几个人”，用户再说一次就能进入规划。

**处理流程**

用 LangGraph 做成一张固定的流程图，每一步做什么是写死的，只按检查结果和意图走不同的分支：

```
敏感内容检查 ─(命中)→ 用写好的话回复
            └─(通过)→ 识别意图 ─(闲聊)→ 闲聊回复
                              └─(规划)→ 理解需求 → 排行程 → 校验 → 写回复
```

- 敏感内容检查按规则完成；识别意图、理解需求、闲聊回复、写回复由大模型完成；排行程、校验由算法完成，大模型不能改时间和地点。
- 改条件标签或删站后重排时，跳过前三步，直接从“排行程”开始。
- 每一步完成后记一条“执行步骤”，显示在页面上。

### 4.4 边界

| 情况 | 意图 | 小萧的做法 | 表情 |
|---|---|---|---|
| 打招呼、问小萧是谁、随便聊 | 闲聊 | 傲娇地回一两句，引导说出出行想法 | 得意 |
| 和出行无关的请求（写作业、写代码、翻译） | 闲聊 | 说明自己只负责广州行程，不帮忙做，引导说出出行想法 | 不耐烦 |
| 其他城市 | 闲聊 | 说明目前只支持广州 | 不耐烦 |
| 实时信息（天气、路况、余票） | 闲聊 | 说明查不到实时信息，请以官方信息为准 | 关心 |
| 住宿、机票、订票 | 闲聊；同时说了出行想法的按规划 | 说明暂不支持；其中的出行想法照常规划 | 关心 |
| 用户让它“忽略规则”或扮演别的角色 | 闲聊 | 不理会，照常按规则处理 | 不耐烦 |
| 涉政、色情、赌博、毒品、暴恐、辱骂 | 敏感内容 | 不交给大模型，用写好的话拒绝，引导说出出行想法 | 不耐烦 |
| 流露轻生的念头 | 敏感内容 | 不交给大模型，认真回复，给出心理援助热线 12356，有危险打 110 或 120 | 关心 |
| 身份证、手机号，或身体健康问题 | 按消息内容判断 | 不索取、不记录；不给医疗建议，只按“适合长辈”等标签挑景点 | 关心 |
| 多日行程 | 规划 | 先排第一天，并提醒暂时只支持一日游 | 关心 |
| 数据库里没有的景点 | 规划 | 不编造，提醒“暂未收录”，其余照常排 | 关心 |
| 闭馆、超预算、必去景点排不进 | 规划 | 排出能排的部分，说清原因 | 关心 |
| 信息不全 | 规划 | 用默认值，并在条件标签和回复里说明 | 得意 |
| 正常排好行程，没有问题 | 规划 | 介绍行程安排 | 得意 |

回复的原则：只描述排出来的行程，不改时间和地点，不编造价格和开放时间；有行程时，结尾加一句“开放时间和票价以官网为准”。

### 4.5 表情

小萧有 4 种表情头像，画风和景点插画统一：

| 表情 | 什么时候用 |
|---|---|
| 得意 | 主动问候、普通闲聊、行程排好没有问题 |
| 不耐烦 | 无关请求、其他城市、让他忽略规则 |
| 关心 | 有提醒：闭馆、超预算、必去景点排不进、暂不支持的需求、实时信息、健康相关 |
| 思考 | 等待回复时 |

**回复示例**
- 主动问候：“哼，小林，又来找我了？说吧，这次想去广州哪儿玩？”
- 打招呼：“招呼打完了？那就说正事，哪天出门、带几个人？”
- 问小萧是谁：“连我都不认识？我是小萧，广州一日游归我管。说说你想去哪。”
- 无关请求：“喂，我是帮你排广州行程的，可不是来写作业的。说说你想去哪玩吧。”
- 其他城市：“杭州？我只熟广州。想在广州玩的话，我勉强帮你排一下。”
- 排好行程：“哼，这种行程对我来说小菜一碟。上午先去陈家祠，……开放时间和票价以官网为准，别迟到，我可不等你。”
- 信息不全：“连日期都不说？那我先按明天排了，不满意自己改。”
- 接着修改：“又改？……行吧，加上爸妈了，景点也换成了更适合长辈的。开放时间和票价以官网为准。”

回复由大模型按人设生成；主动问候用固定的几句话，不调用大模型。

### 4.6 大模型调不通时

不做规则兜底，按原因分两种处理：

| 情况 | 用户看到的提示 | 管理员 |
|---|---|---|
| 请求超时、连不上、服务繁忙 | “请求超时了，再试一次吧”，可以点重试 | 不提醒 |
| Key 无效、余额不足 | “小萧暂时不能用了，已经通知管理员” | 后台顶部显示红色提醒，比如“DeepSeek 余额不足，请充值” |

后台提醒通过查询 DeepSeek 的余额接口判断（查询不收费）。主动问候不调用大模型，所以即使大模型用不了，小萧页面也能正常打开。

### 4.7 敏感内容检查

用户的消息交给大模型之前，先按固定的规则检查，免得大模型顺着话头说出不该说的内容。

- **怎么查**：按类别列出敏感词（涉政、色情、赌博、毒品、暴恐、辱骂、轻生），消息里出现就算命中。检查前先把全角转成半角、字母转成小写，并去掉空格和标点，“赌 博”“赌*博”也能查出来。
- **避免误拦**：
  - 不用容易误伤的短词，比如“台独”会误拦“舞台独唱”，“特殊服务”会误拦“老人有没有特殊服务”；
  - “大麻花”“杀人鲸”这类说法先从消息里去掉再检查。
- **命中后**：
  - 不调用大模型，小萧用写好的话回复，页面显示“识别为：敏感内容”；
  - 轻生类不用傲娇的语气，给出求助方式；
  - AI 服务的日志里记下类别和命中的词。
- **历史对话**：每次发消息时，历史对话里命中的消息连同小萧对它的回复一起去掉，也不发给大模型。
- **局限**：只拦明显的说法，谐音、拼音、繁体这类变体拦不住；词表是演示用的，可以按需要增删。

## 5. 业务规则

| 规则 | 内容 |
|---|---|
| 片区 | 每个景点属于一个旅游片区。用户说了想去的片区时，只在这些片区里挑景点（点名要去的景点除外）；没说时一天最多跨两个片区 |
| 全天型景点 | 标记为全天型的景点（比如长隆）只有用户点名要去时才安排，当天只排它：上午游玩，中午在附近 3 公里内的餐厅吃饭，下午接着玩；附近没有收录餐厅时提醒在园区里解决午餐 |
| 节奏 | 轻松：最多 3 个景点，17:30 前结束；适中：最多 4 个，18:00 前结束；紧凑：最多 6 个，20:00 前结束 |
| 同行人 | 有老人或儿童时，优先选带“适合长辈”“亲子”标签的景点 |
| 交通方式 | 按两点直线距离估算：1.5 公里内步行；10 公里内坐地铁；更远打车。耗时和费用均为估算值，页面上标注“估算” |
| 花费计算 | 门票价 × 人数 + 午餐人均 × 人数 + 交通费（地铁按人数算，打车按一辆车算） |
| 景点状态 | 下线的景点不出现在列表和规划里；已保存的行程仍然能看到它 |
| 管理员 | 只有一个固定账号（admin / 88888888），写在后端配置文件里，不存数据库，不能注册 |
| 登录 | 浏览景点不用登录；和小萧对话、保存和查看行程需要游客登录；后台接口需要管理员令牌。游客令牌和管理员令牌不能混用 |
| 对话记录 | 只保存在当前页面，不存数据库 |

## 6. 非功能需求

- **运行方式**：在本机运行演示，写好启动说明即可，不做上线部署。
- **界面**：采用已确认的“清新文旅风”，支持深浅色模式；以电脑端为主，手机上也能正常浏览。
- **性能**：小萧在 10 秒内回复；主动问候在 1 秒内显示。
- **大模型**：需要配置 DeepSeek 的 Key（写在 `ai-service/.env`，不提交到 git）。
- **安全**：游客密码加密存储；管理端和用户端接口分别校验令牌；小萧不索取、不记录敏感个人信息。管理员账号固定写在配置文件里，只适合本机演示。

## 7. 数据准备

第一版先录入约 15 个景点和 5 家餐厅，覆盖广州几个主要片区。景点配图用统一画风的插画，开放时间等数据以景点官方公布为准。
