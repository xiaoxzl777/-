# 接口文档

## 1. 总体架构

```
浏览器（React，端口 5173）
    │  HTTP + JSON，请求头带登录令牌
    ▼
后端（Spring Boot，端口 8081）──► MySQL
    │  HTTP + JSON（只在本机调用）
    ▼
AI 规划服务（Python FastAPI，端口 8000）──► DeepSeek（没配 Key 时用规则解析）
```

- 前端只调用后端，不直接调用 Python。
- 规划时，后端把上线的景点、开放时间和闭馆日一次性发给 Python。Python 负责理解需求、用贪心算法排行程、校验、写说明，最后把结果返回给后端。Python 不连数据库，也不回调后端。
- 地图由前端用高德 JS API 显示。没有 Key 时显示示意路线。

## 2. 通用约定

- 地址前缀：`http://localhost:8081/api`
- 登录后，请求头带上 `Authorization: Bearer <token>`，令牌 7 天有效
- 统一返回格式：

```json
{ "code": 0, "message": "ok", "data": {} }
```

| code | 含义 |
|---|---|
| 0 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录或登录已过期 |
| 403 | 没有权限（比如游客访问后台接口） |
| 404 | 数据不存在 |
| 503 | AI 规划服务不可用 |
| 500 | 服务器错误 |

- 分页参数：`page`（从 1 开始）、`size`（默认 10）；分页结果为 `{ "list": [], "total": 0 }`
- 日期格式 `2026-09-19`，时间格式 `09:00`

## 3. 登录

### POST /auth/register 注册

```json
// 请求
{ "username": "xiaolin", "password": "123456", "nickname": "小林" }
// 返回 data
{ "id": 2, "username": "xiaolin", "nickname": "小林", "role": "VISITOR" }
```

### POST /auth/login 登录

```json
// 请求
{ "username": "xiaolin", "password": "123456" }
// 返回 data
{ "token": "eyJhbGciOi...", "user": { "id": 2, "username": "xiaolin", "nickname": "小林", "role": "VISITOR" } }
```

### GET /auth/me 当前用户（需登录）

返回 data 同登录结果里的 `user`。

## 4. 景点（不用登录）

### GET /districts 片区列表

```json
// 返回 data（示例）
[ { "id": 1, "name": "老城区（越秀、荔湾）" }, { "id": 2, "name": "珠江新城与广州塔" } ]
```

### GET /pois 景点列表

参数：`districtId`、`type`（SCENIC / RESTAURANT）、`keyword`、`page`、`size`。只返回已上线的。

```json
// 返回 data（示例数据）
{
  "list": [
    { "id": 3, "type": "SCENIC", "name": "示例景点", "districtId": 1, "districtName": "老城区（越秀、荔湾）",
      "illustration": "ancestral-hall", "stayMinutes": 90, "ticketPrice": 10.00, "rating": 4.7,
      "tags": ["历史人文", "适合长辈"], "officialUrl": "https://example.com" }
  ],
  "total": 15
}
```

### GET /pois/{id} 景点详情

在列表字段的基础上，再加 `adminArea`、`address`、`lng`、`lat`、`intro`、`fullDay`、`avgCost`，以及：

```json
{
  "openRules": [ { "weekdays": [2,3,4,5,6,7], "openTime": "09:00", "closeTime": "17:30", "lastEntryTime": "17:00" } ],
  "closedDates": [ { "date": "2026-10-12", "reason": "设备检修" } ]
}
```

`closedDates` 只返回今天及以后的闭馆日。

## 5. AI 规划（需登录）

### POST /plan 生成行程

请求二选一：第一次规划传 `prompt`；修改条件后重排传 `conditions`，这时不再重新理解那句话。

```json
// 第一次规划
{ "prompt": "周六带爸妈逛老城区，想轻松点，预算 500" }

// 修改条件后重排（还可以加 removedPoiIds，表示用户删掉的站，重排时不再选）
{ "prompt": "周六带爸妈逛老城区，想轻松点，预算 500",
  "conditions": { "date": "2026-09-19", "startTime": "09:00", "adults": 1, "seniors": 2, "children": 0,
                  "budget": 400, "pace": "RELAXED", "districtIds": [1], "mustPoiIds": [], "avoidPoiIds": [5], "interests": ["历史人文"] },
  "removedPoiIds": [5] }
```

返回 data（结果不入库）。

先说三个和小萧相关的字段：
- `accepted`：这句话是否被受理为广州一日游需求。为 `false` 时，`conditions` 为空，`items` 为空数组，只看 `reply`。
- `mood`：小萧的表情，取值为 `PROUD` 得意、`ANNOYED` 不耐烦、`CARING` 关心。前端在等待结果时自己显示“思考”表情。
- `reply`：小萧的回复文字。

```json
{
  "accepted": true,
  "mood": "PROUD",
  "conditions": { "date": "2026-09-19", "startTime": "09:00", "adults": 1, "seniors": 2, "children": 0,
                  "budget": 500, "pace": "RELAXED", "districtIds": [1], "mustPoiIds": [], "avoidPoiIds": [], "interests": ["历史人文"] },
  "items": [
    { "seq": 1, "poiId": 3, "name": "示例景点", "type": "SCENIC", "illustration": "ancestral-hall", "lng": 113.2448, "lat": 23.1258,
      "officialUrl": "https://example.com", "startTime": "09:00", "endTime": "10:30", "cost": 30.00,
      "nextMode": "WALK", "nextMinutes": 12, "nextMeters": 850, "nextCost": 0 }
  ],
  "totalCost": 395.00,
  "steps": [
    { "title": "理解需求", "detail": "周六，3 人（含 2 位老人），预算 ¥500，节奏轻松" },
    { "title": "筛选景点", "detail": "老城区周六开放的景点 6 个、餐厅 2 家" },
    { "title": "排出行程", "detail": "按开放时间和路程依次安排 3 个景点，午餐 1 次" },
    { "title": "校验", "detail": "开放时间、衔接时间、预算都已通过" }
  ],
  "reply": "哼，这种行程对我来说小菜一碟。上午先去……开放时间和票价以官网为准，别迟到，我可不等你。",
  "warnings": [ "某景点周一闭馆，没有排进去" ]
}
```

不受理时的返回示例：

```json
{ "accepted": false, "mood": "ANNOYED", "conditions": null, "items": [], "totalCost": 0, "steps": [],
  "reply": "喂，我是帮你排广州行程的，可不是来写作业的。说说你想去哪玩吧。", "warnings": [] }
```

## 6. 行程（需登录，只能操作自己的）

### POST /trips 保存行程

```json
// 请求：把 /plan 返回的结果原样带回，再加标题
{ "title": "周六，带爸妈逛老城区", "prompt": "周六带爸妈逛老城区，想轻松点，预算 500",
  "conditions": { ... }, "items": [ ... ], "totalCost": 395.00 }
// 返回 data
{ "id": 12 }
```

### GET /trips 我的行程列表

参数：`page`、`size`。返回 `list` 里每项包括：`id`、`title`、`tripDate`、`stopCount`、`totalCost`、`createdAt`。

### GET /trips/{id} 行程详情

返回 `id`、`title`、`prompt`、`conditions`、`items`（字段同 /plan）、`totalCost`。

### DELETE /trips/{id} 删除行程

返回 `data` 为空。

## 7. 管理后台（需管理员）

| 接口 | 说明 |
|---|---|
| `GET /admin/districts` | 片区列表 |
| `POST /admin/districts` | 新增片区，请求 `{ "name": "...", "sort": 1 }` |
| `PUT /admin/districts/{id}` | 修改片区 |
| `DELETE /admin/districts/{id}` | 删除片区（片区下还有景点时不允许删） |
| `GET /admin/pois` | 景点列表（含下线的），参数同 `/pois`，外加 `status` |
| `GET /admin/pois/{id}` | 景点详情（含开放时间和闭馆日） |
| `POST /admin/pois` | 新增景点，请求为景点的全部字段（见数据库设计） |
| `PUT /admin/pois/{id}` | 修改景点 |
| `PUT /admin/pois/{id}/status` | 上线 / 下线，请求 `{ "status": "OFFLINE" }` |
| `PUT /admin/pois/{id}/open-rules` | 整体替换开放时间，请求为规则数组（格式同详情里的 `openRules`） |
| `POST /admin/pois/{id}/closed-dates` | 新增闭馆日，请求 `{ "date": "2026-10-12", "reason": "设备检修" }` |
| `DELETE /admin/pois/{id}/closed-dates/{dateId}` | 删除闭馆日 |

## 8. AI 规划服务（Python，只给后端调用）

### POST http://localhost:8000/plan

后端在收到 `/api/plan` 后调用这个接口。请求在前端请求的基础上，再加上当天日期和景点数据：

```json
{
  "prompt": "周六带爸妈逛老城区，想轻松点，预算 500",
  "conditions": null,
  "removedPoiIds": [],
  "today": "2026-09-17",
  "districts": [ { "id": 1, "name": "老城区（越秀、荔湾）" } ],
  "pois": [
    { "id": 3, "type": "SCENIC", "name": "示例景点", "districtId": 1, "lng": 113.2448, "lat": 23.1258,
      "stayMinutes": 90, "fullDay": false, "ticketPrice": 10.00, "avgCost": null, "rating": 4.7,
      "tags": ["历史人文", "适合长辈"],
      "openRules": [ { "weekdays": [2,3,4,5,6,7], "openTime": "09:00", "closeTime": "17:30", "lastEntryTime": "17:00" } ],
      "closedDates": [ "2026-10-12" ] }
  ]
}
```

返回格式和 `/api/plan` 的 `data` 一样，但 `items` 里只有 `poiId` 和时间、费用、交通字段。后端再补上名称、插画、坐标、官网，然后返回给前端。

Python 内部分五步：
1. 判断是否受理：按需求分析第 4 节的边界，判断是不是广州一日游需求。不受理就直接返回小萧的回复；
2. 理解需求：配了 DeepSeek 时由大模型把那句话转成条件，没配时用规则识别；没说的条件用默认值；
3. 筛选候选：当天开放、上线、不在“不去”列表；按片区、兴趣、评分打分；
4. 贪心排程：从出发时间开始，每次选“得分高、路程近、此时能进、不超预算”的下一站；11:30 以后插入一次午餐；
5. 校验和回复：逐站复核，生成提醒并确定表情（有提醒时为“关心”）；配了 DeepSeek 时由大模型按小萧的人设写回复，没配时从模板里挑。

调用 DeepSeek 时，系统提示词里写明小萧的身份、性格、人设规矩和边界。大模型只负责两件事：把那句话转成条件 JSON，以及写回复文字；行程由算法排，大模型不能改时间和地点。

### GET http://localhost:8000/health

返回 `{ "status": "ok", "llm": "deepseek" }`；没配 Key 时 `llm` 为 `"rule"`。
