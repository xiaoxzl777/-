# 接口文档

## 1. 总体架构

```
浏览器（React，端口 5173）
    │  HTTP + JSON，请求头带登录令牌
    ▼
后端（Spring Boot，端口 8081）──► MySQL
    │  HTTP + JSON（只在本机调用）
    ▼
AI 服务（Python FastAPI，端口 8000）──► DeepSeek（没配 Key 时用规则和模板）
```

- 前端只调用后端，不直接调用 Python。
- 和小萧对话时，后端把消息、上线的景点、开放时间和闭馆日一次性发给 Python。Python 负责识别意图、理解需求、用贪心算法排行程、校验、写回复，最后把结果返回给后端。Python 不连数据库，也不回调后端。
- 地图由前端用高德 JS API 显示。没有 Key 时显示示意路线。

### 后端分层

采用标准三层架构：controller 接收请求，service 处理业务，mapper 读写数据库。controller 按管理端和用户端分成两个包，接口地址也对应分开。

```
tour-server/src/main/java/com/tour/
├─ controller/
│  ├─ admin/       管理端 /api/admin/**：管理员登录、片区、景点
│  └─ user/        用户端 /api/user/**：注册登录、浏览景点、小萧对话、行程
├─ service/        业务接口，impl/ 下是实现类
├─ mapper/         MyBatis 接口，SQL 写在 resources/mapper/*.xml
├─ pojo/           entity 数据库实体、dto 请求参数、vo 返回数据
├─ interceptor/    令牌拦截器，管理端和用户端各一个
├─ client/         调用 Python AI 服务
├─ config/         注册拦截器、跨域等配置
├─ common/         统一返回、业务异常、全局异常处理
└─ util/           JWT 工具
```

## 2. 通用约定

- 地址前缀：`http://localhost:8081/api`。用户端接口在 `/api/user` 下，管理端接口在 `/api/admin` 下。下文的接口地址都省略 `/api`。
- 令牌：
  - 游客在 `/user/login` 登录，管理员在 `/admin/login` 登录，各自拿到令牌；
  - 请求头带上 `Authorization: Bearer <token>`，令牌 7 天有效；
  - 游客令牌不能调管理端接口，管理员令牌也不能调需要游客登录的接口。
- 统一返回格式：

```json
{ "code": 0, "message": "ok", "data": {} }
```

| code | 含义 |
|---|---|
| 0 | 成功 |
| 400 | 参数错误，或用户名、密码错误 |
| 401 | 没带令牌，或令牌已过期 |
| 403 | 令牌类型不对（比如游客令牌访问管理端接口） |
| 404 | 数据不存在 |
| 503 | AI 服务不可用 |
| 500 | 服务器错误 |

- 分页参数：`page`（从 1 开始）、`size`（默认 10）；分页结果为 `{ "list": [], "total": 0 }`
- 日期格式 `2026-09-19`，时间格式 `09:00`

## 3. 用户端：注册登录

### POST /user/register 注册

用户名 3 到 20 位（字母、数字、下划线），密码 6 到 20 位，昵称最多 12 个字（不填时和用户名相同）。

```json
// 请求
{ "username": "xiaolin", "password": "123456", "nickname": "小林" }
// 返回 data
{ "id": 2, "username": "xiaolin", "nickname": "小林" }
```

### POST /user/login 登录

```json
// 请求
{ "username": "xiaolin", "password": "123456" }
// 返回 data
{ "token": "eyJhbGciOi...", "user": { "id": 2, "username": "xiaolin", "nickname": "小林" } }
```

### GET /user/me 当前游客（需游客登录）

返回 data 同登录结果里的 `user`。

## 4. 用户端：景点（不用登录）

### GET /user/districts 片区列表

```json
// 返回 data（示例）
[ { "id": 1, "name": "老城区（越秀、荔湾）" }, { "id": 2, "name": "珠江新城与广州塔" } ]
```

### GET /user/pois 景点列表

参数：`districtId`、`type`（SCENIC / RESTAURANT）、`keyword`、`page`、`size`。只返回已上线的。

```json
// 返回 data（示例数据）
{
  "list": [
    { "id": 3, "type": "SCENIC", "name": "示例景点", "districtId": 1, "districtName": "老城区（越秀、荔湾）",
      "illustration": "ancestral-hall", "stayMinutes": 90, "ticketPrice": 10.00, "avgCost": null, "rating": 4.7,
      "tags": ["历史人文", "适合长辈"], "officialUrl": "https://example.com" }
  ],
  "total": 15
}
```

### GET /user/pois/{id} 景点详情

在列表字段的基础上，再加 `adminArea`、`address`、`lng`、`lat`、`intro`、`fullDay`，以及：

```json
{
  "openRules": [ { "weekdays": [2,3,4,5,6,7], "openTime": "09:00", "closeTime": "17:30", "lastEntryTime": "17:00" } ],
  "closedDates": [ { "date": "2026-10-12", "reason": "设备检修" } ]
}
```

`closedDates` 只返回今天及以后的闭馆日。

## 5. 用户端：小萧（需游客登录）

这一组接口的返回都带小萧的表情和回复：
- `mood`：小萧的表情，取值为 `PROUD` 得意、`ANNOYED` 不耐烦、`CARING` 关心。等待回复时，前端自己显示 `THINKING` 思考；
- `reply`：小萧说的话。

### GET /user/chat/greeting 主动问候

打开小萧页面时调用。

```json
// 返回 data
{ "mood": "PROUD", "reply": "哼，小林，又来找我了？说吧，这次想去广州哪儿玩？" }
```

### POST /user/chat 发消息

```json
// 请求
{
  "message": "带上爸妈，想轻松点",
  "history": [
    { "role": "assistant", "content": "哼，小林，又来找我了？说吧，这次想去广州哪儿玩？" },
    { "role": "user", "content": "周六想去老城区逛逛，预算 500" },
    { "role": "assistant", "content": "哼，这种行程对我来说小菜一碟……" }
  ],
  "conditions": { "date": "2026-09-19", "startTime": "09:00", "adults": 1, "seniors": 0, "children": 0,
                  "budget": 500, "pace": "NORMAL", "districtIds": [1], "mustPoiIds": [], "avoidPoiIds": [], "interests": [] }
}
```

- `history`：这条消息之前的最近 10 条对话，`role` 为 `user` 或 `assistant`。
- `conditions`：当前行程的条件，还没有行程时传 `null`。`budget` 为 `null` 表示不限。

返回 data：
- `intent`：`PLAN` 规划 / `CHAT` 闲聊；
- `plan`：规划结果，闲聊时为 `null`。结果不入库，点“保存行程”才保存。

```json
// 规划时
{
  "intent": "PLAN",
  "mood": "PROUD",
  "reply": "又改？……行吧，加上爸妈了，景点也换成了更适合长辈的。开放时间和票价以官网为准。",
  "plan": {
    "conditions": { "date": "2026-09-19", "startTime": "09:00", "adults": 1, "seniors": 2, "children": 0,
                    "budget": 500, "pace": "RELAXED", "districtIds": [1], "mustPoiIds": [], "avoidPoiIds": [], "interests": [] },
    "items": [
      { "seq": 1, "poiId": 3, "name": "示例景点", "type": "SCENIC", "illustration": "ancestral-hall", "lng": 113.2448, "lat": 23.1258,
        "officialUrl": "https://example.com", "startTime": "09:00", "endTime": "10:30", "cost": 30.00,
        "nextMode": "WALK", "nextMinutes": 12, "nextMeters": 850, "nextCost": 0 }
    ],
    "totalCost": 395.00,
    "steps": [
      { "title": "识别意图", "detail": "规划行程，在原来的条件上修改" },
      { "title": "理解需求", "detail": "周六，3 人（含 2 位老人），预算 ¥500，节奏轻松" },
      { "title": "筛选景点", "detail": "老城区周六开放的景点 6 个、餐厅 2 家" },
      { "title": "排出行程", "detail": "按开放时间和路程依次安排 3 个景点，午餐 1 次" },
      { "title": "校验", "detail": "开放时间、衔接时间、预算都已通过" }
    ],
    "warnings": [ "某景点周一闭馆，没有排进去" ]
  }
}
```

```json
// 闲聊时
{ "intent": "CHAT", "mood": "ANNOYED", "reply": "喂，我是帮你排广州行程的，可不是来写作业的。说说你想去哪玩吧。", "plan": null }
```

`items` 里每一站的字段：

| 字段 | 说明 |
|---|---|
| `seq` | 第几站，从 1 开始 |
| `poiId`、`name`、`type`、`illustration`、`lng`、`lat`、`officialUrl` | 地点信息；`type` 为 `RESTAURANT` 的是午餐 |
| `startTime`、`endTime` | 到达和离开的时间 |
| `cost` | 这一站的花费（门票或餐费 × 人数） |
| `nextMode`、`nextMinutes`、`nextMeters`、`nextCost` | 去下一站的方式（`WALK` 步行 / `METRO` 地铁 / `TAXI` 打车）、耗时、距离、费用，都是估算值；最后一站为 `null` |

### POST /user/plan 按条件重排

改了条件标签或删了某一站之后调用，不再识别意图。删掉的站由前端加进 `avoidPoiIds`，同时从 `mustPoiIds` 里去掉。

```json
// 请求
{ "conditions": { "date": "2026-09-19", "startTime": "09:00", "adults": 1, "seniors": 2, "children": 0,
                  "budget": 400, "pace": "RELAXED", "districtIds": [1], "mustPoiIds": [], "avoidPoiIds": [5], "interests": [] } }
```

返回 data 和 `/user/chat` 规划时的格式一样，`intent` 固定为 `PLAN`。

## 6. 用户端：行程（需游客登录，只能操作自己的）

### POST /user/trips 保存行程

```json
// 请求：把 plan 里的结果带回，再加标题和需求原话
{ "title": "周六，带爸妈逛老城区", "prompt": "周六想去老城区逛逛，预算 500；带上爸妈，想轻松点",
  "conditions": { ... }, "items": [ ... ], "totalCost": 395.00 }
// 返回 data
{ "id": 12 }
```

`prompt` 是这次对话里被识别为规划的消息，按顺序用“；”连接，最长 500 字。

### GET /user/trips 我的行程列表

参数：`page`、`size`。返回 `list` 里每项包括：`id`、`title`、`tripDate`、`stopCount`、`totalCost`、`createdAt`。

### GET /user/trips/{id} 行程详情

返回 `id`、`title`、`prompt`、`conditions`、`items`（字段同上）、`totalCost`、`createdAt`。

### DELETE /user/trips/{id} 删除行程

返回 `data` 为空。

## 7. 管理端

### POST /admin/login 管理员登录（不用令牌）

```json
// 请求
{ "username": "admin", "password": "88888888" }
// 返回 data
{ "token": "eyJhbGciOi...", "name": "管理员" }
```

只核对配置文件 `application.yml` 里 `tour.admin` 下的固定账号，不查数据库。不一致时 code 为 400。

### 其余接口（需管理员令牌）

| 接口 | 说明 |
|---|---|
| `GET /admin/districts` | 片区列表 |
| `POST /admin/districts` | 新增片区，请求 `{ "name": "...", "sort": 1 }` |
| `PUT /admin/districts/{id}` | 修改片区 |
| `DELETE /admin/districts/{id}` | 删除片区（片区下还有景点时不允许删） |
| `GET /admin/pois` | 景点列表（含下线的），参数同 `/user/pois`，外加 `status` |
| `GET /admin/pois/{id}` | 景点详情（含开放时间和全部闭馆日） |
| `POST /admin/pois` | 新增景点，请求为景点的全部字段（见数据库设计） |
| `PUT /admin/pois/{id}` | 修改景点 |
| `PUT /admin/pois/{id}/status` | 上线 / 下线，请求 `{ "status": "OFFLINE" }` |
| `PUT /admin/pois/{id}/open-rules` | 整体替换开放时间，请求为规则数组（格式同详情里的 `openRules`） |
| `POST /admin/pois/{id}/closed-dates` | 新增闭馆日，请求 `{ "date": "2026-10-12", "reason": "设备检修" }` |
| `DELETE /admin/pois/{id}/closed-dates/{dateId}` | 删除闭馆日 |

## 8. AI 服务（Python，只给后端调用）

### GET http://localhost:8000/greeting

参数：`nickname`。从问候模板里随机挑一句，返回 `{ "mood": "PROUD", "reply": "..." }`。

### POST http://localhost:8000/chat

后端收到 `/api/user/chat` 后调用。请求在前端请求的基础上，再加上当天日期、片区和上线的景点数据：

```json
{
  "message": "带上爸妈，想轻松点",
  "history": [ { "role": "user", "content": "周六想去老城区逛逛，预算 500" } ],
  "conditions": null,
  "today": "2026-09-17",
  "districts": [ { "id": 1, "name": "老城区（越秀、荔湾）" } ],
  "pois": [
    { "id": 3, "type": "SCENIC", "name": "示例景点", "districtId": 1, "lng": 113.2448, "lat": 23.1258,
      "stayMinutes": 90, "fullDay": false, "ticketPrice": 10.00, "avgCost": null, "rating": 4.7,
      "tags": ["历史人文", "适合长辈"],
      "openRules": [ { "weekdays": [2,3,4,5,6,7], "openTime": "09:00", "closeTime": "17:30", "lastEntryTime": "17:00" } ],
      "closedDates": [ "2026-10-12" ] }
  ]
}
```

返回格式和 `/api/user/chat` 的 `data` 一样，但 `items` 里只有 `poiId` 和时间、费用、交通字段。后端再补上名称、插画、坐标、官网，然后返回给前端。

处理分五步：
1. 识别意图：配了 DeepSeek 时由大模型判断，同时提取条件；没配时按关键词判断（见需求分析 4.3）。闲聊就直接写回复并返回；
2. 理解需求：把消息转成条件。传了 `conditions` 时，只覆盖这句话提到的条件；没传时，没说的条件用默认值；
3. 筛选候选：当天开放、上线、不在“不去”列表；按片区、兴趣、同行人标签、评分打分；
4. 贪心排程：从出发时间开始，每次选“得分高、路程近、此时能进、不超预算”的下一站；11:30 以后插入一次午餐；
5. 校验和回复：逐站复核，生成提醒并确定表情（有提醒时为“关心”）；配了 DeepSeek 时由大模型按小萧的人设写回复，没配时从模板里挑。

### POST http://localhost:8000/plan

后端收到 `/api/user/plan` 后调用。请求为 `conditions`、`today`、`districts`、`pois`，直接从上面的第 3 步开始，返回格式同 `/chat`。

调用 DeepSeek 时，系统提示词里写明小萧的身份、性格、人设规矩和边界。大模型只负责三件事：判断意图、把消息转成条件 JSON、写回复文字。行程由算法排，大模型不能改时间和地点。

### GET http://localhost:8000/health

返回 `{ "status": "ok", "llm": "deepseek" }`；没配 Key 时 `llm` 为 `"rule"`。
